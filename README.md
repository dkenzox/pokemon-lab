# Matchup Lab — personal local Pokémon Champions comparator

Open http://127.0.0.1:8768/ while the Node server is running. This complements Pokebase with a personal comparison workspace. Plain HTML/CSS/JS, a small Node server, a vendored MIT simulator and one current JSON catalogue. No public deployment, accounts, community features or team database.

From this directory, with Node 22.13 or newer (native SQLite support):

```sh
npm ci
npm start
```

Keep the terminal running. Opening index.html as a file or using a Python static server cannot provide the calculation endpoints. The server binds only to 127.0.0.1. To use another port: `MATCHUP_PORT=8770 npm start`.

## Saved scenarios and the Pokémon editor

The scenario bar replaces the former test presets. **New scenario** starts a named workspace with your Pokémon and empty comparison lists. Switch scenarios through the searchable menu; the actions menu offers rename, duplicate and removal with Undo. Each scenario keeps its own sets, battle conditions, threats and Speed comparisons. Changes autosave after 500 ms; the bar shows Saved locally or a retryable save error. Concurrent tabs use revision checks to prevent silently overwriting newer changes.

The editor uses a searchable Pokémon/form picker with type filters and type, name, Pokédex number and Base Speed sorting, described ability radio cards, searchable items and four move slots. The name on the main Pokémon panel opens a sprite-backed form switcher when related forms exist; it retains legal moves, stat points and battle modifiers, while adjusting a required Mega Stone or ability. When adding a threat or Speed comparison, a scrollable shortlist shows the 20 highest-ranked eligible species for the selected Singles/Doubles format. A toggle filters all ranked species to the 20 highest-picked with a legal damaging move that is 2× or 4× effective against your selected form, considering each species’ five most-used reported moves. Cards show the qualifying move and multiplier. This type screen does not calculate damage or KO odds; abilities, items and battle conditions can change the result. These ranks describe overall pick order, shared by forms, and are not opponent-specific encounter odds; selecting a card loads a suggested set for review before adding it. The move selector includes type/category filters, descriptions, power, accuracy and PP; the selected attack is chosen from those four slots and controls outgoing damage and move priority. All four slots are also visible on the main panel. Nature can be chosen by name or increased/decreased stat. Stat rows show base and level-50 values, colored bars, minus/plus and MIN/MAX controls, and independent −6 through +6 stage steppers. HP has no stat stage. Status and Tailwind are icon checkboxes. MAX uses only the remaining 66-point budget. Usage percentages are shown only where the current ranked snapshot supplies that exact marginal value; missing percentages are left blank. Suggested sets are optional starting points within the editor, not workspace presets.

Persistence uses Node's built-in SQLite driver: no database service or additional package is needed. The default database is `data/matchup-lab.sqlite`, outside the static server's allowed files. It persists across browser and server restarts. Existing v2 browser saves migrate on the first database connection; the original browser copy remains available for recovery. Set `MATCHUP_DB=/absolute/path/workspace.sqlite` to choose another location. Stop the server before copying the database for a backup. Catalogue refreshes leave scenarios and personal sets intact.

## Stats, damage and order

Level 50; SP 0–32 per stat, at most 66 total. HP = base + SP + 75; other stats = floor((base + SP + 20) × nature). No configurable IVs or traditional EVs. All 25 natures are available. Both editor and server enforce legality and the budget. Mega forms require their own stone, preventing Choice Scarf.

Damage runs a fresh Champions simulator battle for each of the 16 equally likely damage rolls. Its rounding, type, STAB, ability, item, weather, terrain, screens, burn, spread and survival effects apply. KO chance counts actual zero-HP outcomes after survival hooks, including repeated damage values separately. For example, Life Orb Adamant Kingambit’s Kowtow Cleave into the default Mega Metagross gives 151–182 damage and 13/16 = **81.25% KO**. This differs from the old illustrative prototype’s 18.75% example because the sets and calculation are now real.

Probabilities are **conditional on a connecting move**, not a total chance including accuracy, optional critical hits or random secondary effects. The critical toggle forces a crit, including the engine’s stage bypass. Guaranteed critical moves retain their forced crit. Fresh switch-in effects run, followed by configured stage offsets. Megas start already evolved. No previous turns, protection, substitutes, hazards or end-turn residual damage are assumed. Speed cases start at full HP; Current HP applies to your Pokémon in both damage directions. Threat HP defaults to full HP. Partners are neutral; doubles spread mode has two opposing targets and an ally. One-target mode removes the other active slots. Sucker Punch calculates damage when the target has not acted and is using a damaging move; its chance of succeeding is not included. Psychic Terrain still blocks priority against a grounded target, and the matchup names this reason instead of presenting an unexplained zero. Stomping Tantrum calculates its normal first-use 75 power; its tooltip explains that a failed previous move doubles it to 150. Conditional multi-hit, OHKO accuracy, charging, random-target and other turn-history-dependent moves show a calculation gap rather than an inaccurate numeric KO chance. Doubles Trace needs an explicit copy-target board and is also marked unsupported. The upstream engine flags Aura Guard’s interaction with ability bypass as unconfirmed; that combination is blocked.

The damage table places threats on the left and your Pokémon on the right. Each row can use its own Pokémon and set: duplicate a threat, choose Edit this row beside your Pokémon, and select another form or set without changing the main Pokémon or other rows. Use main set removes that row override. Speed comparison continues to use the main Pokémon. Each matchup shows both attack directions with separate damage intervals, target HP thresholds, exact KO percentages and expandable rolls. Your outgoing move and the incoming threat move can be chosen independently in each row from their respective four-move sets; both choices stay with that comparison. Target HP, Defense and Sp. Def are visible beside the outgoing result so spread differences are explicit. These are independent fresh damage checks, not a simulated exchange. When your Pokémon has Intimidate, the threat row shows its effective Attack stage after switch-in and configured modifiers; the incoming damage calculation uses that stage. The threat editor shows the effective Attack stage (−1 when Intimidate is triggered against an eligible threat). Its +/− buttons adjust an additional manual offset without applying Intimidate twice. Each Intimidate row has a Trigger Intimidate checkbox; turning it off removes the ability’s switch-in Attack drop only for that damage comparison. Other ability interactions still run automatically. Battle-condition screens can be set for your side and the opponent side; threat-specific screens can also be set in the threat editor. Aurora Veil assumes it is already active, so snow is not required to keep the toggle active. Screen tooltips explain Singles versus Doubles.

Speed uses the simulator’s automatic ability/item/field/stage/status effects. Priority and fractional order effects apply before Speed; Trick Room reverses Speed within equal priority. Ties and random-order items remain explicit. Stat stages, SP and status controls update in place without replacing focused controls or collapsing result tables. Poison is omitted because residual damage is outside this calculation. SP sliders fill the full track at 32. The move selector opens at the viewport center and locks background scrolling while its list scrolls. Weather uses illustrated icons; terrains use matching type icons and color. The terrain selector describes each effect, and the selected terrain has a keyboard-accessible tooltip. Every Speed row exposes only Tailwind, paralysis and its Speed stage; attack stages stay in the Pokémon editor. Both tables show name, ability/nature descriptions, item sprites and the complete nonzero SP spread on separate lines. Each opponent comparison reports your Speed in that board’s weather context. Scenario columns change nature, Speed SP and item, clearing other SP so the scenario stays legal. They are benchmarks, not usage sets.

This is a pinned community implementation, not an official game simulator. The app exposes its assumptions and gaps; it does not claim complete battle simulation coverage.

## Refresh and recovery

Click **Update data** or run:

```sh
npm run update
```

This fetches the official current roster and current ranked API summary, validates all generated sets and roster coverage, writes a candidate JSON and atomically replaces the catalogue only after validation. A failed refresh keeps the last good cache. `data/update-report.json` lists additions, removals, changed mechanics/suggestions and coverage counts. Snapshot timestamps alone do not count as changed sets. Only one current transformed usage cache is retained, with no historical API archive, permanent mirror or replacement service. There is no periodic polling.

Move selectors fetch the full reported ranked move percentages on demand from the battle API. Each entry is a marginal for the shown Singles/Doubles format, with base-species scope stated for Mega forms. Unreported legal moves show an unavailable percentage, never a fabricated zero. One current transformed cache is kept in `data/move-usage.json`, reused for 24 hours and invalidated by a changed catalogue snapshot. Failed fetches retain and label the last good data.

Mechanics stay pinned during a data-only refresh. To explicitly check and update the MIT Champions engine:

```sh
npm run update:engine
```

The script checks the official Smogon source commit, builds a candidate, rebuilds the catalogue and runs the verification suite before replacing engine/data. A failed candidate is discarded. One previous MIT engine is retained for rollback; restart `npm start` after a successful engine change. The no-change path is verified; replacement with a different upstream commit has not been exercised against a live newer release. A regulation transition requires reviewing the official regulation URL/roster/date configuration in `scripts/catalogue.cjs`; the updater refuses an expired regulation rather than falsely claiming current eligibility.

## Public deployment

The GitHub Pages build is in `.github/workflows/pages.yml`. Every push to `main` rebuilds the static page with `node scripts/build-pages.cjs`. For local changes: edit files here, run `npm run verify`, commit, and push `main`. The Pages URL is `https://dkenzox.github.io/pokemon-lab/`.

The calculation service runs on Render Free from `render.yaml` and should be linked to the same GitHub repository with automatic deploys enabled. It is API only (`MATCHUP_HOSTED=1`); scenarios and personal sets remain in browser storage on GitHub Pages. There is no account sync: export personal sets for backup, and use the same browser to access saved scenarios. The API URL is `https://pokemon-lab-api.onrender.com` by default. If Render assigns a different URL, set the `apiBase` default in `web-client.js` and push `main`.

Render Free may take time to wake after inactivity, and the server's sprite and usage caches are temporary. The authoritative catalogue is committed in `data/catalogue.json`; refresh it locally with `npm run update`, review the changed data, then commit and push. The in-page refresh button is unavailable on Pages because static assets cannot be changed from the browser.
